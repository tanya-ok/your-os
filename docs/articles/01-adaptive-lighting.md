# A workspace that follows the light, not your life

Personal OS has a simple architectural boundary: the environment may change with time, while the person keeps control of their state and commitments.

## A quiet daily transition

The lighting engine resolves a phase from an explicitly configured schedule, manual override or optional solar settings. It interpolates a small set of color tokens rather than mounting a different dashboard. Active projects, task state and notes remain visible. A shift from morning to evening never assigns energy, mood, health values or a workload.

The Main Rhythm chart is a separate illustrative 24-hour ribbon with five fictional anchors. It has a moving current-time indicator and can be paused. It is not a seasonal calendar or a scientific prediction of capacity.

## Contrast and movement

Readable text is checked at representative points in each color transition, using the [WCAG contrast reference](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). This checks named foreground/background pairs, not every accessibility requirement. Keyboard focus, labels, dialogs and narrow layouts need their own verification.

The interface respects reduced motion. A user may choose a static scene, stronger contrast or a manual phase without explaining a medical reason. None of these preferences requires inference or an external request.

## Keep the authority boundary

Lighting is deterministic local presentation. AI is optional, selected context is visible, and each model send is explicit. A reply never executes actions. Note edits use preview, freshness checks, atomic write and session undo. An external Obsidian edit must not be silently replaced by a stale preview.

The public examples tell one connected fictional week: a Home theme, a small garden experiment, learning how to listen and a career question about life after AI. Their purpose is to convey a workflow without importing a person's notes, identity or memory.

The architecture is described in the [original public article](https://tanya.engineer/blog/personal-os-architecture/). This edition documents its own checked scope and limitations. The next useful evidence is observing how people with different schedules use it, before adding more automation.
