# Implement the agreed adaptation

Carry out the agreed local plan and the repository instructions. Check the working tree, take the required snapshot and keep other people's changes out of your commits. Do not push, publish or change visibility without permission.

For ordinary projects use the existing Projects flow: create, update, rename the display title, archive and restore. Areas are managed in Setup. Do not add code for one more project. Renaming a title keeps the file ID; archiving does not delete notes.

If a new domain or page was agreed, implement its source adapter, page logic, navigation and empty and error states. Create fictional fixtures only; never copy real notes or a private persona. Check new inputs, scope boundaries and actions. Do not present a placeholder as a working integration.

Keep the default synthetic navigation unless the plan changes it: Movements: Main, Today, GTD, Calendar, Work; Home: Home, Health, Library; Garden: Career, Learning, Future; AI Agent; utilities Graph, Projects, Review, Setup. `src/navigation.js` is the authority for this order. Do not replace distinct pages with one generic card.

Keep Markdown, frontmatter and stable line references. Use safe paths and `atomicWrite`. Task, project, `Inbox.md` and weekly-review edits go through preview, source freshness check, apply and session undo. New page state is a Markdown record defined in `lib/record-paths.js`; never add a SQLite table as the only copy of user data. Records are Markdown. A save writes the canonical `.md` file in the Main Vault before it reports success: page records under `Records/`, preferences under `Settings/` (see `docs/storage-contract.md`). This covers Work sessions, completed work, time blocks and meeting preparation; Home weeks; Health practices and sleep; Library; Career and Learning records; Future exploration; Main decisions, context, priorities, garden and practices; manual Energy/Mood check-ins; and local calendar events. SQLite holds only the retrieval index, revision bookkeeping, feed and native calendar caches and technical state; deleting it loses no record. The selected Rhythm anchor, a running focus countdown, unsent capture drafts and unsaved AI conversations stay in page memory. A record save is refused when its file changed outside the app; reload, then edit. Every manual value is set by the person. Never infer health or energy from the clock or lighting.

For lighting, check timezone, date boundaries, wake from sleep, manual override, missing coordinates and solar edge cases where supported. Check intermediate colours, keyboard focus, reduced motion and the static fallback. Active projects stay visible in every phase.

Rhythm is a day chart with five synthetic anchors, the current time in the chosen timezone and gentle motion that can be paused. Do not add a Japanese calendar, glyphs or an invented scientific origin. Respect reduced motion and the static scene. Anchor choice and manual Energy/Mood do not change with lighting; the clock shows time, not the state of the person.

Main Vault, Person-self-model and AI-Model use only explicitly configured roots (`VAULT_PATH`, `PERSON_SELF_MODEL_PATH`, `AI_MODEL_PATH`); never search for other vaults. Model vaults hold reviewed observations: a candidate in `_inbox/` cites hashed source notes and stays out of retrieval until a person accepts, defers or rejects it on the Review page. Acceptance writes a review to `Reviews/` and the claim to `Accepted/`; only an accepted claim with a matching human review can be selected as agent context. An agent cannot draft or accept candidates. Model vault writes need `ALLOW_MODEL_VAULT_WRITES=true` outside the demo. An agent query runs local SQLite FTS5 keyword retrieval over the selected notes and records only, with vault, path and line references in the preview. It is not embeddings, semantic search or a memory of the person. Every provider send needs fresh context and explicit consent.

After frontend changes run build, check, relevant tests and desktop and mobile visual QA. For an adapter, check empty and unavailable sources, refusal outside scope, preview freshness and undo. Check reload and restart for records, Work Start/End without duplicates, Home weeks, Career and Learning records, local calendar CRUD, an external edit of a record file and the conflict it causes. Local calendar events are Markdown records. Feeds are user-supplied read-only iCal or RSS/Atom URLs; definitions live in `Settings/sources.md`, private URLs in local credential storage outside Git, fetched items in a SQLite cache. Adding or listing a source does not fetch; only an explicit Refresh does, and a failed refresh keeps the cache. No Google OAuth, API writes or background polling. Check SSRF, redirect and size limits and that errors never show URL credentials. Setup holds the Home programme (title, start date, length 1-52 weeks), focus length (default 60, 1-180 minutes), work hours, news and calendar visibility, news limit, shortcuts and lighting. ⌘K / Ctrl K captures a note or task through a Markdown preview, ⌘⇧K / Ctrl Shift K searches pages, Alt 1-9 navigates. The cool blue-gray palette stays in every lighting phase. If a check is not available, say so. Report actual behaviour, evidence, placeholders, limits and rollback; a passing build alone is not readiness.
